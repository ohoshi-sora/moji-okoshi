# 文字起こしデスクトップアプリ 設計書

- 日付: 2026-07-29(初版) / 2026-07-29 改訂(エンジンをmlx-whisperに変更)
- 対象: macOS (Apple Silicon) デスクトップGUIアプリ

## 目的

Zoomの録画ファイル(.mov / .mp4)やApple ボイスメモの音声ファイル(.m4a)を
ドラッグ&ドロップで読み込み、日本語の文字起こしを行い、
プレーンテキストとして保存できるデスクトップアプリを作る。

## 改訂メモ: faster-whisper → mlx-whisper への変更

初版はfaster-whisper(CTranslate2)で実装したが、CTranslate2はApple Silicon の
GPU/Neural Engineに対応しておらずCPU推論のみだった。文字起こし速度を優先するため、
Apple製のMLXフレームワークを使う`mlx-whisper`に切り替える。

トレードオフとして、`mlx_whisper.transcribe()`はファイル全体を処理し終えてから
結果をまとめて返す作りで、セグメント単位のリアルタイム表示ができない。
このためUIは「処理中はインジケーターを表示し、完了時に全文を一括表示」に変更する
(この変更はユーザーが速度を優先して明示的に許容した)。

## スコープ

含む:
- 1ファイルずつのドラッグ&ドロップ/手動選択による読み込み
- mlx-whisperによる日本語文字起こし(言語固定)
- 完了後、文字起こし結果を一括でテキストエリアに表示(処理中はインジケーター表示)
- プレーンテキスト(.txt)としての保存、クリップボードへのコピー
- モデルサイズの選択(small / medium / large-v3-turbo)

含まない(将来の拡張候補として明記するのみ):
- 複数ファイルのバッチ/キュー処理
- SRT/VTTなどタイムスタンプ付き出力
- 話者分離(スピーカーラベル)
- 特定フォルダの自動監視による取り込み

## 前提・制約

- 対象Macは Apple Silicon (M系)。`mlx-whisper`はApple製のMLXフレームワーク経由で
  Metal GPUを使用するため、CPU推論のfaster-whisperより高速に動作する。
- モデルは`mlx-community`がHugging Face上で配布している変換済みモデルを使用する
  (例: `mlx-community/whisper-medium-mlx`, `mlx-community/whisper-large-v3-turbo`)。
  存在は`huggingface_hub`のAPIで実際に確認済み。
- 文字起こし対象は日本語中心のため、`language="ja"`に固定し、
  言語自動検出のオーバーヘッドと誤検出リスクを避ける。
- `mlx_whisper.transcribe()`はブロッキング呼び出しで、セグメント単位の
  コールバック/ストリーミングは公開APIとして提供されない。そのため
  セグメント単位のリアルタイム表示は行わず、完了時に全文をまとめて表示する。

## アーキテクチャ

```
┌─────────────────────────────────────────┐
│  MainWindow (PySide6)                    │
│  - ドラッグ&ドロップ / ファイル選択ボタン  │
│  - モデルサイズ選択 (dropdown)            │
│  - 実行ボタン / 進捗バー                 │
│  - 結果表示 (QTextEdit, 読み取り専用)     │
│  - 保存ボタン (.txt書き出し)              │
└───────────────┬───────────────────────────┘
                │ シグナル/スロット
┌───────────────▼───────────────────────────┐
│  TranscribeWorker (QThread)               │
│  - mlx_whisper.transcribe() を呼び出す     │
│  - 完了/エラーをシグナルでUIに送る          │
└───────────────┬───────────────────────────┘
                │
┌───────────────▼───────────────────────────┐
│  mlx-whisper (Apple MLX / Metal GPU)      │
│  - mlx-communityの変換済みモデルを使用     │
│  - 言語固定: ja                            │
└─────────────────────────────────────────────┘
```

単一のPythonプロセス内でGUIとモデル推論が完結する(プロセス間通信なし)。
モデル推論はUIスレッドをブロックしないよう別スレッド(QThread)で実行する。

## コンポーネント詳細

### MainWindow
- ドラッグ&ドロップ領域 + 「ファイルを選択」ボタン
  - 対応拡張子: `.mov` `.mp4` `.m4a` `.wav` `.mp3`
  - 非対応拡張子はドロップ時点で弾いてダイアログ表示
- モデルサイズ選択: `small` / `medium` / `large-v3-turbo`
  - デフォルトは `medium`(速度と精度のバランス。`large-v3-turbo`は
    デコーダー層を削減した蒸留版で、`medium`より高速かつ高精度な選択肢)
- 「文字起こし開始」ボタン、処理中インジケーター(不確定進捗バー)
  - モデルダウンロード中・推論中を通してインジケーターを表示し続け、
    完了時に結果を表示する(セグメント単位の途中経過は表示しない)
- 結果表示エリア(`QTextEdit`、読み取り専用)
  - 完了時に全文を一括表示
- 「テキストを保存」「クリップボードにコピー」ボタン
- キャンセルボタン(処理中のスレッドを中断)

### TranscribeWorker (QThread)
- `mlx_whisper.transcribe(file_path, path_or_hf_repo=repo_id, language="ja")`を呼び出す
- 完了時に全文をシグナルでメインスレッドへ送信、失敗時はエラーをシグナルで送信
- キャンセル要求を受けたら、処理完了後の結果送信をスキップする
  (呼び出し自体はブロッキングのため、実行中の処理を途中で止めることはできない)

### モデル管理
- 選択したモデルは初回呼び出し時にHugging Face経由で自動ダウンロードされ、
  `~/.cache/huggingface`にキャッシュされる(mlx_whisperが内部で処理、アプリ側での実装は不要)
- ダウンロード失敗時(ネットワーク未接続等)はエラーダイアログを表示する。
  「文字起こし開始」ボタンが再度有効になるため、同じ操作でリトライできる

## データフロー

1. ユーザーがファイルをドロップ/選択する
2. ファイルパスを`TranscribeWorker`に渡してスレッドを開始する
3. `mlx_whisper.transcribe()`が音声を読み込み、ブロッキングで文字起こしを行う
4. 完了後、全文をシグナルでメインスレッドに送信し、`QTextEdit`に一括表示する
5. 全文を保存/コピー可能にする

## エラーハンドリング

| ケース | 挙動 |
|---|---|
| 非対応拡張子のファイルをドロップ | ドロップ時点で弾き、ダイアログでサポート形式を案内 |
| モデルダウンロード失敗 | エラーダイアログ表示。「文字起こし開始」ボタンが再度有効になり、押し直すことでリトライできる |
| 処理中の例外(壊れたファイル等) | 例外をキャッチしてダイアログ表示、アプリ自体は継続動作 |
| 処理中のキャンセル | `mlx_whisper.transcribe()`はブロッキング呼び出しのため、実行中の計算そのものは止められない。キャンセル操作は「完了後の結果表示をスキップする」動作に留まる(この制約はUIに明示する) |

## 開発・パッケージング

- 開発環境: Python仮想環境(`venv`) + `pip install mlx-whisper pyside6`
- 第一段階はローカルでのスクリプト実行(`python main.py`)で動作確認
- 最終的に`PyInstaller`で`.app`化し、ダブルクリックで起動できるようにする
  (`.app`化は動作確認が済んだ後の後続タスクとする)
